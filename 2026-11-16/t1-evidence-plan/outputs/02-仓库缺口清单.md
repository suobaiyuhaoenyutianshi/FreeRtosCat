## 6. E. Flash / RAM 与 Bootloader + 分区约束（本次盘点的关键结论）

### 6.1 硬数据

- FLASH 64 KB（`0x08000000`–`0x0800FFFF`），中容量 F103 页大小 **1 KB**。
- RAM 20 KB；链接后已用 14,480 B，**主栈可用余量 6,008 B**（含链接脚本预留的 512 B heap + 1 KB stack 区域）。
- App 体积：MinSizeRel 43,440 B；Debug(-Og) 48,120 B。
- 当前链接脚本：[stm32f103c8tx_flash.ld](../../../stm32f103c8tx_flash.ld) 固定 `FLASH ORIGIN = 0x08000000, LENGTH = 64K`，无分区概念。

### 6.2 结论一：A/B 双槽 OTA 不可行

- 双槽至少需要 `2 × 43,440 = 86,880 B`，已超过 64 KB；用 Debug 构型更不可能。
- 因此 T1 只能做 **单槽 OTA**：Bootloader 接收 → 擦 App 区 → 边写边校验 → 末尾整包 CRC32。
- CRC 失败或中途掉电时，**旧固件已被覆盖**，但 Bootloader 常驻，可停在升级模式重传，不会变砖。
- 这一限制必须写进 README「已知限制」，也是面试时“你怎么取舍”的答案（D2 决策点）。

### 6.3 结论二：两种可行布局

**方案 A（建议基线，Boot 给足 8 KB）**

| 区域 | 地址范围 | 大小 | 说明 |
|---|---|---|---|
| Bootloader | `0x08000000`–`0x08001FFF` | 8,192 B | 裸机 UART + Flash 写 + CRC32 + 跳转 |
| App | `0x08002000`–`0x0800F7FF` | 55,296 B（54 KB） | 向量表重定位到 `0x08002000` |
| 参数 A | `0x0800F800`–`0x0800FBFF` | 1,024 B | 1 页 |
| 参数 B | `0x0800FC00`–`0x0800FFFF` | 1,024 B | 1 页，A/B 交替 |

- App 余量：MinSizeRel **11,856 B（21.4%）**；Debug **7,176 B（13.0%）**。

**方案 B（备选，Boot 压到 4 KB）**

| 区域 | 地址范围 | 大小 |
|---|---|---|
| Bootloader | `0x08000000`–`0x08000FFF` | 4,096 B |
| App | `0x08001000`–`0x0800F7FF` | 59,392 B（58 KB） |
| 参数 A/B | `0x0800F800`–`0x0800FFFF` | 2 × 1,024 B |

- App 余量：MinSizeRel **15,952 B（26.9%）**；Debug **11,272 B（19.0%）**。
- 前提：Bootloader 必须 ≤4 KB。带 HAL UART 的版本通常做不到，需要寄存器级/LL + 无 `printf` + 软件 CRC32。**W3 先按 A 做，实测 Boot 体积后再决定是否切 B。**

### 6.4 分区改造必须动的地方（P1–P3 的硬性清单）

| 项 | 现状 | 必须改 |
|---|---|---|
| 链接脚本 | 单一 `FLASH ORIGIN=0x08000000, LENGTH=64K` | App 版改 `ORIGIN=0x08002000, LENGTH=54K`；加 `ASSERT` 防止踩参数区；Boot 版单独脚本 |
| 向量表重定位 | [system_stm32f1xx.c](../../../Core/Src/system_stm32f1xx.c#L91-L100) 中 `USER_VECT_TAB_ADDRESS` **被注释**，VTOR 保持 `0x08000000` | 启用宏并设 `VECT_TAB_OFFSET`，或在 App `main()` 最前面写 `SCB->VTOR = 0x08002000` |
| 诊断读取 VTOR | [app_mpu6050.c](../../../Core/Src/app_mpu6050.c#L60) 用 `((uint32_t*)SCB->VTOR)[16 + TIM2_IRQn]` | 重定位后仍要能取到 TIM2 向量，逻辑成立但需回归验证 |
| 启动跳转 | 无 | Boot 需关中断、设 MSP = `*(uint32_t*)APP_BASE`、跳 `*(uint32_t*)(APP_BASE+4)`、必要时 `HAL_DeInit()` |
| CRC | HAL CRC 模块**未启用**（[stm32f1xx_hal_conf.h](../../../Core/Inc/stm32f1xx_hal_conf.h#L43) 注释） | 用软件 CRC32（省 Flash）或启用 HAL CRC（多占空间） |
| `.bin` | 无生成步骤 | 加 `objcopy` post-build |
| 参数区擦写 | 无 | 1 KB 页擦除；写入前关中断/停机；擦除期间 CPU 停 → 1 ms 电机环抖动数十 ms |
| IWDG | 约 410 ms（Prescaler 4 / Reload 4095 / LSI≈40 kHz），Boot 中无 tick | 每页擦写后喂狗；Boot 不能用 `HAL_Delay`，用 DWT 延时 |
| UART | App 用 FreeRTOS 队列 + DMA（[app_usart2_dma.c](../../../Core/Src/app_usart2_dma.c)） | Bootloader 不能复用，需裸机轮询 USART2（921600） |
| RAM 缓冲 | 主栈余 6,008 B | OTA 不能整包缓存；建议 1 KB 页缓冲 + 流式校验 |

### 6.5 结论三：参数写 Flash 与 1 ms 电机环冲突（提前记录）

- F103 从 Flash 取指时执行 Flash 擦写会阻塞 CPU，页擦除约 20–40 ms，1 ms 电机环会丢数十拍。
- 因此：**参数写入只能在“电机断使能 / 启动阶段 / 产测停机态”执行**；产测脚本的 `test param` 必须先 `App_Motor_Cmd(0)`。
