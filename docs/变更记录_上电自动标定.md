- 记录时间：2026-11-17
- 涉及文件：`Core/Src/app_encoder.c`、`Core/Inc/app_encoder.h`、`Core/Src/main.c`
- 未提交（仅工作区改动，构建已验证）

## 一、要解决的问题

`m_l[2]` / `m_r[2]` 是测速 M/T 算法的相位权重，由左右编码器 A 相各自的占空比决定：

```c
m_l[0] = 2 * DUTY_L;   m_l[1] = 2 - 2 * DUTY_L;
m_r[0] = 2 * DUTY_R;   m_r[1] = 2 - 2 * DUTY_R;
```

这里的 DUTY 是**编码器 A 相的高电平时间 / 完整周期**，不是电机 PWM 占空比。A 相高、低电平时间不完全相等（霍尔安装、磁钢一致性、比较器阈值都会带来差异），左右轮各测各的，所以 `DUTY_L = 0.500`、`DUTY_R = 0.490` 本来就应该不同。

原来的数据是手工用串口测的。电机更换后旧数据失效，表现为测速权重与真实波形不匹配、速度估计有偏差，车不够平。产品化不可能每台都人工测，因此改为上电自动测量。

> 上一版曾把这里做成“电机占空比增益”（比较两轮计数后乘到 PWM 上），方向理解错了，已全部撤销。本版只做编码器 A 相占空比的自动测量与 `m_l/m_r` 刷新。

## 三、测量原理

A 相一个完整周期由“高电平段 + 低电平段”组成。中断里已经记录了相邻边沿的时间戳 `t1 → t0`，因此每来一个边沿都能得到刚结束那一段的时长：

- 边沿后读到 A = 0（下降沿）→ 刚结束的是高电平 → 累加到 `cal_high_ticks`；
- 边沿后读到 A = 1（上升沿）→ 刚结束的是低电平 → 累加到 `cal_low_ticks`。

统计窗口结束后：

```
DUTY = 高电平总时长 / (高电平总时长 + 低电平总时长)
```

因为只在单轮转动时统计，另一轮保持 0，所以不会串扰。

### 时序（每个轮子）

| 阶段 | 时长 | 作用 |
| --- | --- | --- |
| 起转 | 200 ms | 跳过电机加速段，速度未稳时不统计 |
| 统计 | 300 ms | 累计高/低电平与边沿数 |
| 停转 | 100 ms | 等滑行结束，避免残余边沿干扰下一轮 |

左右各一轮，共约 1.2 s。

### 为什么不“转几毫秒”

A 相一个完整周期本身约几毫秒，几毫秒只能采到一两个周期，量化噪声和边沿抖动会直接进入结果。300 ms 窗口通常能平均上百个周期，占空比可以稳定到千分位。

## 四、失败保护

满足任一条件即判定该轮测量失败，保留原来的 `g_duty_l/g_duty_r`，不用坏数据覆盖：

- 有效边沿数 < `CAL_MIN_EDGES`（20）；
- 高电平或低电平总时长为 0（编码器断线 / 电机没转）；
- 算出的占空比超出 `[0.30, 0.70]`。

串口输出：

```
CAL L: 500/1000
CAL R: 490/1000
```

失败时：

```
CAL L: FAIL, keep 500/1000
```

## 七、使用注意与边界

1. **必须车轮架空再上电**：标定会真实驱动电机，左右各转约 0.6 秒。
2. 标定结果只保存在 RAM，每次上电重新测量，不写 Flash。
3. 本标定修正的是**测速权重**，不是电机输出补偿。如果左右轮在相同 PWM 下实际转速不同，仍需要另外的 PWM 补偿或编码器距离闭环。
4. 电机占空比低于启动死区时轮子不转，会因边沿数不足而判定失败并保留旧值；`CAL_PWM_DUTY = 0.40` 需按实际电机调整。
5. `App_Encoder_StartCalibration / EndCalibration` 旧接口保留，返回当前全局 DUTY，未参与本流程。
