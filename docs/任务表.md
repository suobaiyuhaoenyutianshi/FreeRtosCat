# 任务表：栈 / 优先级 / 通信 / 中断

> 数据日期：2026-11-16（提交 `d00db29`）
> 来源：`Core/Src/main.c`、各 `app_*.c`、`freeRTOS/Inc/FreeRTOSConfig.h`
> 说明：本文的栈与优先级是**创建参数（设计值）**；实测高水位与执行时间在 T1-P5 补齐，当前标 `待实测`。

## 1. 任务总表

| 任务 | 入口函数 | 栈（字 / 字节） | 优先级 | 触发方式 | 周期 | 主要工作 |
|---|---|---|---|---|---|---|
| motor | `App_Motor_Proc` | 128 / 512 | 5 | TIM2 更新中断 `vTaskNotifyGiveFromISR` | 1 ms | 左右轮速度环 PID → PWM；电池电压归一化 |
| ctrl | `App_Control_Task` | 384 / 1,536 | 4 | `att` 任务 `xTaskNotifyGive` | ≈5 ms（事件驱动） | 串级 PID、倒地停机、电量灯 `App_Bat_Pro` |
| att | `App_Attitude_Task` | 256 / 1,024 | 3 | `vTaskDelayUntil` | 5 ms | I2C 读 MPU6050、互补滤波、覆盖式邮箱、通知 ctrl |
| rc | `APP_rc_rxTask` | 512 / 2,048 | 2 | USART3 DMA 空闲中断 → 二值信号量 | 帧驱动 | 临界区拷贝帧、解析 `move`、调试打印 |
| UART2_TX | `vUSART2_TxGateKeeperTask` | 128 / 512 | 2 | 发送队列 + DMA 完成信号量 | 帧驱动 | USART2 DMA 发送、释放动态缓冲 |
| MemMon | `prvMemoryMonitorTask` | 256 / 1,024 | 1 | `vTaskDelay` | 100 ms 喂狗 / 2000 ms 打印 | 栈高水位、堆统计、IWDG |
| idle | FreeRTOS 空闲任务 | 128 / 512（内核静态） | 0 | 就绪即运行 | — | 空闲 |

- 软件定时器任务：**不存在**（`configUSE_TIMERS = 0`）。
- `configMAX_PRIORITIES = 7`，当前实际使用 0–5。
- 动态任务栈合计：128+384+256+128+512+256 = **1,664 字 = 6,656 B**。

### 优先级设计理由（当前实现）

| 任务 | 为什么在这个位置 |
|---|---|
| motor（5） | 1 ms 硬节拍，必须最先响应；只做两次 PID 与 PWM 写入，执行时间短 |
| ctrl（4） | 控制主环，等姿态新帧后计算；比 att 高，保证写完邮箱立即被消费 |
| att（3） | 5 ms 采样，I2C 阻塞读约 0.4 ms；比 ctrl 低，避免采样抢占控制计算 |
| rc（2）/ UART2_TX（2） | 人机/调试链路，允许延迟；同优先级轮转 |
| MemMon（1） | 只做统计与喂狗，最低应用优先级，避免干扰控制 |
| idle（0） | 内核空闲 |

## 2. 堆预算（heap_4，`configTOTAL_HEAP_SIZE = 9,728`）

| 项 | 估算 | 说明 |
|---|---|---|
| 6 个动态任务栈 | 6,656 B | 见上表 |
| 6 个 TCB | ≈576 B | 按 96 B/个估算（结构 + 8 B 块头对齐） |
| 块头 | 48 B | 6 × 8 B |
| 2 个队列 | ≈208 B | 姿态邮箱（1×`Attitude_t`）、打印队列（`char*` × `TX_QUEUE_LEN`） |
| 2 个二值信号量 | ≈160 B | `xLineReady`、`xTxDmaSem` |
| 常驻合计 | ≈7,648 B | 静态余量约 2,080 B |
| 打印临时缓冲 | 峰值 ≈1,632 B | 队列 5 份 + DMA 1 份，单份上限 272 B |

> 结论：静态余量约 2 KB，但打印峰值会再占约 1.6 KB，**实际余量需上板看 MemMon 的 `Min ever`**。
> 注意：`FreeRTOSConfig.h` 的堆总账注释仍写“6 个任务栈 6144B”，与当前 6,656 B 不一致（rc 从 256 字加到 512 字后未同步），以本表与 `size` 输出为准，注释待 P7 修正。

## 3. 通信与共享资源

| 路径 | 机制 | 语义与约束 |
|---|---|---|
| att → ctrl | 长度 1 队列 + `xQueueOverwrite` / `xQueuePeek` | 覆盖式邮箱；读者拿到“最新且完整”的快照，不保证历史 |
| att → ctrl | 任务通知 `xTaskNotifyGive` / `ulTaskNotifyTake(pdTRUE)` | 事件驱动；`pdTRUE` 清空累积计数 |
| TIM2 ISR → motor | `vTaskNotifyGiveFromISR` + `portYIELD_FROM_ISR` | 1 ms 节拍；中断优先级必须 ≥5 |
| USART3 DMA ISR → rc | 二值信号量 `xLineReady` | 一帧一通知；帧拷贝在临界区完成 |
| rc / 调试 → UART2_TX | `char*` 队列 + DMA 完成信号量 | 所有权转移；发送完成由 UART2_TX 释放 |
| 编码器读取 | `__disable_irq()` 快照多字段 | 保证 `dir/phase/t0/t1` 来自同一时刻 |
| 控制 ↔ 电机 | 函数调用 + PID setpoint 写 | motor 优先级更高，写入是单字段 32 位，无锁 |
| 互斥量 | **0 个**（`configUSE_MUTEXES=1` 未使用） | 优先级反转实验的空白点（T1-P5） |

### 共享数据与保护方式

| 数据 | 写者 | 读者 | 保护 |
|---|---|---|---|
| `s_ready_buf`（遥控帧） | USART3 ISR | rc 任务 | `taskENTER_CRITICAL` 整体拷贝 |
| `s_dma_buf[2]` | DMA | ISR | 双缓冲 + 换缓冲重装 |
| `x_at_T`（姿态邮箱） | att | ctrl / 其他 | 队列内部临界区（按值拷贝） |
| `dir_l/phase_l/t0_l/t1_l` 等 | EXTI ISR | 任意任务 | `__disable_irq()` 快照 |
| `Volt`（电池电压） | ADC ISR | ctrl | 32 位单字写，读一次即可 |
| `g_diag` | 多处 | 调试器 | `volatile`，仅诊断 |

## 4. 中断优先级

| 中断 | 优先级 | 用途 | 调用 FreeRTOS API | 备注 |
|---|---|---|---|---|
| SysTick | 15 | 内核 tick（1 kHz） | 是（内核） | `configKERNEL_INTERRUPT_PRIORITY = 15<<4` |
| TIM2 | 5 | HAL 1 ms 时基 + 通知 motor | 是 | `HAL_IncTick()` + `vTaskNotifyGiveFromISR` |
| USART3 | 5 | 蓝牙空闲/错误 | 是 | 二值信号量 |
| DMA1_Channel3 | 6 | USART3 RX DMA | 是（经 HAL 回调） | 空闲事件回调里给信号量 |
| DMA1_Channel7 | 5 | USART2 TX DMA | 是 | TX 完成回调给信号量 |
| EXTI3 / EXTI15_10 | 6 | 编码器 A 相边沿 | 否 | 高频，不能压过 TIM2 |
| ADC1_2 | 6 | 电池采样 | 否 | TIM3 TRGO 100 Hz |
| TIM1 / TIM3 / TIM4 | 6 | PWM、ADC 触发 | 否 | 当前未开更新中断 |

> **隐式顺序约定**：`MX_*_Init()` 内部会先把 ADC/TIM 设为 0、USART3 设为 7，随后由 `main.c` 的“中断优先级统一编排”覆盖为 5/6。任何在 `MX_*_Init()` 与统一编排之间插入的中断使能，都可能破坏这个约定。

## 5. 创建顺序与句柄依赖

1. `App_Control_Init()` / `App_Motor_Init()` 只初始化 PID，不创建任务。
2. `xTaskCreate(ctrl)` **必须先于** `xTaskCreate(att)`：att 的创建参数需要用 ctrl 句柄。
3. `App_USART2_Init()` 内部创建 `UART2_TX` 任务并保存句柄 `usart2`；`main.c` 随后注册监控。
4. `vRegisterTaskForMonitoring()` 必须在 `vStartMemoryMonitor()` 之前调用。
5. 调度器启动前已创建队列/信号量/任务；历史调试记录（[HAL tick 停摆](调试记录_HAL_Tick停摆.md)）指出这一阶段的临界区曾导致中断被屏蔽，**改动初始化顺序必须回归 `B1/B2` 与 TIM2 中断计数**。
