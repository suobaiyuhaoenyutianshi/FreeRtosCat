> 方法：`git archive HEAD` 导出到工作区外临时目录构建，避免工作区残留影响。

## 2. 复现命令

```powershell
$tmp = Join-Path $env:TEMP "t1_baseline"
if (Test-Path $tmp) { Remove-Item -Recurse -Force $tmp }
New-Item -ItemType Directory -Path $tmp | Out-Null
$zip = Join-Path $env:TEMP "t1_base.zip"
git archive --format=zip -o $zip HEAD
Expand-Archive -Path $zip -DestinationPath $tmp -Force
Set-Location $tmp

cmake --preset Debug;      cmake --build --preset Debug
cmake --preset MinSizeRel; cmake --build --preset MinSizeRel
cmake --preset Release;    cmake --build --preset Release
```

## 3. 结果

| 构型 | 优化参数 | FLASH（size / ld） | RAM | 结果 |
|---|---|---|---|---|
| Debug | `-Og -g3` | 48,184 B / 48,184 B（73.52%） | 14,480 B（70.70%） | PASS |
| MinSizeRel | `-Os -g0 -DNDEBUG` | **43,504 B / 43,504 B（66.38%）** | 14,480 B | PASS |
| Release | `-Os -g0` 后又追加 `-O3 -DNDEBUG` | 51,220 B / 51,220 B（78.15%） | 14,480 B | PASS |

- `size` 明细（Debug）：`text 48,080 + data 104 + bss 14,376`。
- `ld --print-memory-usage` 与 `size` 本次完全一致；RAM 的 `size` 口径为 `data + bss`。
- RAM 未分配（主栈 MSP 可用）：20,480 − 14,480 = **6,000 B**（链接地址上到 `_estack` 为 6,008 B，含 8 B 对齐间隙）。

## 4. 结论与规则

1. **发布统一用 MinSizeRel**：43,504 B，相比 Debug 省 4.7 KB。
2. **Release 预设不可用于发布**：`CMAKE_C_FLAGS_RELEASE` 的 `-O3` 追加在工具链 `-Os` 之后，实际生效 `-O3`，体积比 Debug 还大 3.0 KB。
3. **Flash 预算**（T1 分区方案 A：Boot 8 KB + App 54 KB + 参数 2×1 KB）：
   - App 区域 55,296 B；
   - 按 MinSizeRel 计算余量 **11,792 B（21.3%）**；
   - 按 Debug 计算余量 **7,112 B（12.9%）**。
4. 任何批次合入前记录本表；App 余量低于 4 KB 时暂停新增功能并上报。
